# رسالة لمبرمج Flutter — الربط مع السيرفر الحقيقي

يمكنك نسخ القسم التالي وإرساله لمبرمج Flutter كما هو أو بعد تخصيص الدومين.

---

## نص جاهز للإرسال

**الموضوع: خطوات ربط التطبيق مع السيرفر الحقيقي (بدل اللوكال)**

عند الربط مع السيرفر الحقيقي يرجى التالي:

**1. ضبط Base URL حسب البيئة**
- على اللوكال: استخدم عنوان اللوكال كما هو حالي (مثلاً `http://localhost:8000` أو `http://10.0.2.2:8000`).
- على السيرفر الحقيقي: غيّر الـ Base URL إلى عنوان الـ API على السيرفر، مثلاً:
  - `https://claudsoft.com`
  - بدون إضافة `/api` أو `/api/student` في نهاية الـ base؛ المسارات تُضاف عند كل طلب (مثلاً `/api/student/login`, `/api/student/catalog`).

**2. تسجيل الدخول والتوكن**
- عند الاتصال بالسيرفر الحقيقي، **تسجيل الدخول** يجب أن يكون ضد **نفس السيرفر** (نفس الـ Base URL).
- احفظ التوكن من الاستجابة: `response.data['data']['token']` (أو المسار المكافئ في الكود).
- **لا تستخدم توكن صادر من اللوكال** عند الطلب إلى السيرفر الحقيقي — كل بيئة لها توكن خاص بها.

**3. طلب قائمة الكورسات (الكتالوج)**
- المسار: **GET** `{baseUrl}/api/student/catalog`
- مطلوب في كل طلب: هيدر **`Authorization: Bearer <التوكن_المحفوظ>`**
- بدون هذا الهيدر السيرفر يرجع 401 ولن تظهر الكورسات.

**4. مثال للطلبات المطلوبة**
- تسجيل الدخول: `POST {baseUrl}/api/student/login`  
  Body (JSON): `{"email":"...","password":"..."}`  
  الاستجابة تحتوي على `data.token` — احفظه.
- قائمة الكورسات: `GET {baseUrl}/api/student/catalog`  
  Headers: `Authorization: Bearer <token>`, `Accept: application/json`

**5. إن كان التطبيق Flutter Web**
- تأكد أن الـ Base URL يستخدم `https://` عند الربط بالسيرفر.
- إن ظهر خطأ CORS في المتصفح، أخبر الباكند؛ تم إعداد CORS من جهتهم ويمكنهم مراجعة `config/cors.php` و `CORS_ALLOWED_ORIGINS` في `.env`.

**مراجع في المشروع (للتفاصيل والأمثلة):**
- `docs/API_STUDENT_ROUTES.md` — كل مسارات الـ API والاستجابات.
- `docs/FLUTTER_CATALOG_CALL.md` — أمثلة استدعاء الكتالوج (Dio / http) وحفظ التوكن.
- `docs/LOCAL_VS_SERVER_FLUTTER.md` — الفرق بين اللوكال والسيرفر وما يلزم ضبطه.

## خطأ: type 'String' is not a subtype of type 'num?'

إذا ظهر هذا الخطأ عند تحميل الكورسات، معناه أن نموذج (model) Flutter يتوقع رقماً (`num`/`int`/`double`) بينما الـ API كان يرجِع القيمة كنص. تم من جهة الباكند تصحيح الاستجابة بحيث كل الحقول الرقمية تُرجَع كأرقام (مثل `id`, `duration_in_hours`, `sort_order`, `completion_percentage`, `enrollment_id`, `reading_time`, `duration`). بعد تحديث الـ API على السيرفر يفترض أن يختفي الخطأ.

إن استمر الخطأ: في Flutter يمكن عند قراءة الـ JSON تحويل القيمة إلى رقم عند الاستقبال، مثلاً: `json['duration_in_hours'] is int ? json['duration_in_hours'] : (double.tryParse(json['duration_in_hours']?.toString() ?? '0') ?? 0)`.

## خطأ: Failed host lookup: 'claudsoft.com' (بعد البناء على الجوال)

الرسالة: **The connection errored: Failed host lookup: 'claudsoft.com'**

- **المعنى:** الجهاز (الجوال) لم يستطع **حل اسم الدومين** (DNS) — أي أن الطلب لم يصل إلى السيرفر بسبب الشبكة أو DNS، وليس بسبب الـ API نفسه.
- **يظهر غالباً:** عند تشغيل التطبيق على جوال حقيقي بعد البناء، بينما على اللوكال/المحاكي يشتغل.

**ما الذي يتحقق منه Flutter / المستخدم:**

1. **اتصال الجوال بالإنترنت:** التأكد أن الـ WiFi أو بيانات الجوال مفعّلة وأن هناك اتصال (فتح متصفح والذهاب لأي موقع).
2. **الدومين صحيح ومتاح:** من نفس الجوال فتح المتصفح والدخول إلى `https://claudsoft.com` — إن لم يفتح فالمشكلة من الشبكة أو الدومين على هذا الجهاز/الشبكة.
3. **عدم استخدام localhost على الجوال:** في البناء (release) الـ Base URL يجب أن يكون `https://claudsoft.com` (أو الدومين الفعلي) وليس `localhost` أو `127.0.0.1` — لأن الجوال لا يصل لـ localhost على جهاز الكمبيوتر.
4. **استخدام HTTPS:** التأكد أن الـ URL يبدأ بـ `https://` للسيرفر الحقيقي.
5. **شبكات مقيدة:** إن كان الجوال على شبكة شركة/جامعة قد تحجب بعض الدومينات، تجربة شبكة أخرى (مثل بيانات الجوال).

**من جهة الباكند:** لا يوجد تعديل مطلوب؛ المشكلة من إمكانية وصول الجوال للدومين (شبكة/DNS).

## ملخص في نقطتين

1. **Base URL = عنوان السيرفر الحقيقي** عند التشغيل ضد السيرفر، وتسجيل الدخول من التطبيق ضد نفس هذا العنوان.
2. **كل طلب محمي (catalog, courses, profile)** يحتاج هيدر: **`Authorization: Bearer <token>`** باستخدام التوكن المُرجَع من تسجيل الدخول على نفس السيرفر.
