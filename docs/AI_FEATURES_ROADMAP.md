# خارطة ميزات الذكاء الاصطناعي المقترحة (LMS + Laravel AI SDK)

ملف مستقل يجمع أفكار ميزات يمكن إضافتها على المدى القصير والمتوسط، مع التركيز على التكامل مع **Laravel AI SDK** ونمط **`laravel_ai_models`** + **الوكلاء (Agents)** + **سجلات الاستخدام** حيث ينطبق.

> هذا المستند **خطة ومنتج** وليس مواصفة تنفيذ جاهزة. يمكن اختيار البنود حسب الأولوية وحذف ما لا يناسب المؤسسة.

---

## 1. الوضع المرجعي في المشروع (موجز)

- محركات موازية عبر `config/ai.php` (`AI_APPLICATION_ENGINE`, `AI_BLOG_ENGINE`, `AI_DOCS_ENGINE`, `AI_QUESTIONS_ENGINE`).
- نماذج Laravel AI مع **قدرات (capabilities)** مثل `blog.generate`, `docs.refine`, `questions.generate`, `content.general`.
- مسارات إدارية مرتبطة بالتوليد: مدونة، توثيق، توليد أسئلة (طلب + مراجعة + حفظ)، إنشاء أسئلة مباشرة في بنك الأسئلة مع ربط كورس/اسم درس.

كل ميزة جديدة مقترحة أدناه يمكن أن تتبع نفس الأنماط: **مفتاح محرك اختياري في config**، **صلاحيات أدوار**، **تسجيل في `laravel_ai_logs`**، **واجهة Blade بسيطة أو API**.

## 2. ميزات موجهة لدور **الأدمن**

### 2.1 إدارة المحتوى والكورسات

| الميزة | الوصف | القيمة للأدمن |
|--------|--------|----------------|
| مساعد إعداد الدرس | من لوحة التحكم: تلخيص، أهداف تعلّم، أسئلة مراجعة سريعة، إعادة صياغة فقرة | تسريع النشر وتوحيد الجودة |
| مساعد وصف الكورس | توليد وصف تسويقي/تعليمي من نقاط عريضة أو مخطط | توفير وقت كتابة |
| مراجعة جودة النص | اقتراحات وضوح، تبسيط لغوي، تنبيه مصطلحات غامضة | تقليل مراجعات يدوية متكررة |
| توليد عناوين فرعية وهيكل درس | من نص طويل أو PDF مستخرج (لاحقاً) | هيكلة المحتوى |

### 2.2 بنك الأسئلة والتقييم

| الميزة | الوصف |
|--------|--------|
| تدقيق مجموعة أسئلة | فحص اتساق الصياغة، تكرار المعنى، اقتراح تحسين دون تعديل تلقائي |
| اقتراح بدائل خاطئة | لأسئلة الاختيار من متعدد بناءً على السياق والمستوى |
| تحويل نوع السؤال (مسودة) | مثال: من مقالي إلى اختيار متعدد — مع مراجعة يدوية إلزامية |
| وسوم وفرز ذكي | اقتراح وسوم/صعوبة/تصنيف بناءً على النص (مع موافقة الأدمن) |

### 2.3 التشغيل، المراقبة، والحوكمة

| الميزة | الوصف |
|--------|--------|
| لوحة مراقبة AI | عدد الطلبات، أخطاء، زمن استجابة تقريبي، توكنز إن توفرت من الـ SDK |
| حدود الاستخدام | حد يومي/شهري لطلبات AI حسب الدور أو لمستخدم إداري |
| تفعيل ميزات لكل دور | تشغيل/إيقاف: توليد أسئلة، مساعد درس، إلخ |
| قوالب موجهات (Prompts) | تخزين نسخ معتمدة للمؤسسة مع إصدارات وتتبع من عدّلها |
| سجل مساءلة | من نفّذ أي إجراء AI ومتى (ربط `user_id` + نوع العملية) |

### 2.4 التواصل والدعم الداخلي

| الميزة | الوصف |
|--------|--------|
| مساعد صياغة إعلانات ورسائل | تذكيرات، إعلان صيانة، رسائل جماعية بلهجة موحدة |
| FAQ داخلي للأدمن | إجابات عن إجراءات المنصة (لاحقاً: RAG على وثائق داخلية) |

### 2.5 التقارير والجودة (مع بيانات المنصة)

| الميزة | الوصف |
|--------|--------|
| تلخيص نشاط فترة | من إحصائيات موجودة: تسجيلات، نشاط كورسات، تنبيهات — مع نص تفسيري اختياري |
| تنبيه كورسات راكدة | قائمة كورسات بلا تفاعل + اقتراح إجراءات (إشعار، أرشفة، تحديث محتوى) |
| فحص محتوى حساس (تنبيه فقط) | إشعار للمراجعة البشرية وليس حظراً تلقائياً دون سياسة واضحة |

### 2.6 الأمان والامتثال

| الميزة | الوصف |
|--------|--------|
| سياسة الاحتفاظ بسجلات المحادثات/الطلبات | مدة حذف تلقائي أو أرشفة |
| فصل بيئات المفاتيح | مفاتيح تجريبية vs إنتاج، ومنع استخدام الإنتاج من بيئة تطوير |
| توثيق “ما يُرسل للمزود” | جدول حقول يُشارك مع المدراء القانونيين |

## 3. ميزات موجهة لدور **المدرّس** (إن وُجد في المنصة)

| الميزة | الوصف |
|--------|--------|
| مساعد داخل محرر الدرس | تلخيص، أمثلة، أسئلة سريعة، شرح مبسّط |
| تعليقات إرشادية على واجب مقالي | معايير + نقاط قوة/ضعف + اقتراح تحسين (الدرجة قرار المدرّس) |
| توليد رubric تقييم | جدول معايير من وصف النشاط |
| اقتراح موارد إضافية | روابط/مواضيع للقراءة (مع تحقق يدوي من الجودة) |

## 4. ميزات موجهة لدور **الطالب**

| الميزة | الوصف | ملاحظة حوكمة |
|--------|--------|----------------|
| مساعد الدرس (شرح سؤال) | “اشرح لي” ضمن حدود نص الدرس | منع تسريب اختبارات كاملة |
| بطاقات مراجعة | من محتوى الدرس | اختياري وحسب سياسة المؤسسة |
| تلميحات خطوة بخطوة | للتمارين البرمجية/الحسابية | بدون إعطاء الحل النهائي جاهزاً إن رُغب |
| تلخيص شخصي للمراجعة | من ملاحظات الطالب + مقتطفات مسموحة | |

## 5. ميزات **عامة / تقنية** (تدعم كل ما سبق)

| الميزة | الوصف |
|--------|--------|
| قدرات جديدة في `LaravelAiModel` | مثل `tutor.explain`, `admin.audit_text`, `questions.review` مع فلترة في لوحة الموديلات |
| وكلاء (Agents) متخصصة | وكيل JSON منظم للتقارير، وكيل نص حر للشرح |
| طوابير (Queues) للمهام الطويلة | توليد كبير، دفعات أسئلة، مع إشعار عند الاكتمال |
| Webhooks أو إشعارات | عند فشل التوليد أو اكتمال دفعة |
| اختبارات تكامل | اختبارات وهمية للمزود (fake agent) كما في أنماط المشروع الحالية |

## 6. مراحل تنفيذ مقترحة (مرنة)

1. **المرحلة أ — تشغيل وثقة:** لوحة مراقبة، سجلات، حدود استخدام، مساءلة.
2. **المرحلة ب — إنتاجية الأدمن:** مساعد إعداد الدرس/الكورس، مراجعة نص، تدقيق بنك الأسئلة (قراءة فقط + اقتراحات).
3. **المرحلة ج — المدرّس:** مساعد المحرر، rubric، تعليقات إرشادية على الواجبات.
4. **المرحلة د — الطالب:** مساعد الدرس ضمن سياسة صارمة + تلميحات.
5. **المرحلة هـ — متقدم:** RAG على وثائق داخلية، دفعات، طوابير، تكاملات إضافية.

---

## 7. مخاطر يجب توثيقها قبل التوسع

- **الخصوصية:** بيانات الطلاب والواجبات تُرسل لمزود خارجي — يحتاج موافقة/سياسة.
- **الدقة:** المخرجات ليست مصدر حقيقة تعليمية — دائماً مراجعة بشرية للقرارات الحرجة.
- **التكلفة:** التوكنز والحدود المالية لكل مزود.
- **الانحياز والمحتوى غير المناسب:** فلترة وتنبيه وليس الاعتماد الكامل على النموذج.
